# AI 扫码修复与复验记录（2026-10-10）

## 采用的要求

嘉立创有效包装二维码按 C 编号和二维码数量直接入库，OCR、提取和重排调用为零。普通照片仅使用一次 llama.cpp PaddleOCR-VL，之后复用保存结果；不恢复传统 PP-OCR，不做区域重扫或方向重扫。项目沿用扫描时的固定选择，库存、项目明细和操作历史原子提交。

此前基础修复见 [首次验收记录](scan-import-verification.md)。本轮搜索及核验修复已保存于 `7375a5b`；本次续作补齐候选截短保护、裁决一致性检查、评估工具复用和文档。

## 问题与处理

| 原问题 | 当前处理 |
|---|---|
| 重排 JSON 截断后静默回退 | 严格 Schema/类型校验，提取 512、重排 1200 tokens；截断只重试一次同一文本；失败保存阶段错误，启发式结果不自动入库。 |
| 错字、内部空格或后缀误判 | 去除型号内部空格，后缀保持完整。长 C/R/L 型号前六字符内的一处已知字形误读，须品牌、封装、等价标值和唯一完整目录身份共同支持。 |
| 品牌与目录冲突 | 已复现 Altium 的 YAGEO 型号被记录为 Uniroyal。沿明确 C 关联拉取完整型号一致的供应商记录，不覆盖冲突记录或猜测修正品牌。 |
| 电气规格核验不足 | 单位换算比较 C/R/L，比较明确的电压、电流、功率、容差；小写单位、品牌简称及不同主参数类型的冲突也阻止入库。未知字段显示未知。 |
| 描述型标签被猜成型号 | 提取间距、针数、排数、安装方式等原文观察。外形尺寸不当作间距，无唯一厂家身份保持核查。 |
| 数量始终为 1 | 使用原文唯一有效数量；数量缺失、冲突、超界须核查。 |
| 跨库重复与身份混用 | 完整身份为来源与外部 ID；同 C 编号及同完整型号且已知规格不冲突时合并，冲突的品牌/规格分别保留。人工确认传完整身份。 |
| 候选截短后误判唯一 | SQL、单次召回或最终候选池达到限制时保留 `retrieval_truncated`，截短候选不能自动入库。 |
| 重排同时选中和排除同一记录 | 校验下标范围及裁决一致性，矛盾结果返回 `inconsistent_decision`。 |
| 不同照片共用空二维码指纹 | 图片摘要去重，识别声明合并并发；重试、重新评估及核查不再次 OCR。 |
| 历史数字 ID 疑似跨库写错 | 提供只读审计清单，不猜测修复；库存已删除形成的历史引用缺失单列。 |

数值别名触发器迁移、动态嘉立创来源规范化及旧 PP-OCR 停用已在基础修复中实施，本次保留。
